# Документация: Bluetooth (BLE) интеграция Trackify и Moto Lap Timer

Данная документация описывает функционал передачи трек-файлов между аппаратным GPS логером (ESP32) и мобильным приложением (Flutter) посредством Bluetooth Low Energy (BLE).

---

## 1. Функционал GPS логера (ESP32 - Trackify.gnss_module)

### Переход в режим беспроводной синхронизации (Wireless Sync)
- По умолчанию логер при наличии спутников находится в режиме ожидания (`READY`) или ведет запись (`LOGGING`).
- **Активация режима:** Долгое нажатие (4 секунды) на физическую кнопку устройства активирует режим **Wireless Sync** (одновременно поднимаются BLE сервер и WiFi точка доступа).
- **Индикация:** 
  - На OLED дисплее отображается экран "Wireless Sync", параметры WiFi (`Trackify` / `12345678`), статус BLE (`Trackify`) и надпись "Waiting for App...".
  - Светодиод (NeoPixel) мигает двойной вспышкой циклически бирюзовым цветом (`Cyan`).
- **Имя устройства в BLE:** Устройство рекламирует себя под именем `Trackify`.
- **Выход из режима:** Повторное короткое нажатие на кнопку возвращает логер в стандартный режим работы (`IDLE`), беспроводные интерфейсы (BLE и WiFi AP) отключаются, запускается опрос GPS модуля.

### Протокол работы

Логер реализует GATT-сервис со следующими UUID:
- **Service UUID:** `4fafc201-1fb5-459e-8fcc-c5c9c331914b`
- **Command Characteristic:** `beb5483e-36e1-4688-b7f5-ea07361b26a8` (Свойства: `WRITE`, `WRITE_NR`)
- **Data Characteristic:** `2c27702b-a010-4ea5-a228-4efb7965aa1b` (Свойства: `NOTIFY`)

#### Команды (от телефона к логеру через Command Characteristic)
1. `LIST` — запрос списка файлов на SD-карте.
2. `GET <filename>` — запрос на скачивание конкретного файла (например, `GET log_001.bin` или `GET /log_001.bin`).
3. `WIFI` — запрос учетных данных для прямого подключения по Wi-Fi.

#### Формат данных и ответов (от логера к телефону через Data Characteristic / Notifications)

##### 1. Ответ на `LIST`:
Файлы передаются построчно в формате `<имя_файла>;<размер_в_байтах>\n`:
```text
log_000.bin;285400
log_001.bin;1054320
END_LIST\n
```
*Если корень SD не удалось открыть, возвращается:* `ERROR: Failed to open root\nEND_LIST\n`.

##### 2. Ответ на `GET <filename>`:
1. **Стартовый пакет (заголовок передачи):**
   ```text
   FILE:<filename>:<filesize>\n
   ```
   *Пример:* `FILE:log_001.bin:285400\n`
2. **Пакеты с содержимым файла:**
   Бинарные данные передаются чанками через BLE Notifications. Размер чанка подстраивается под согласованный MTU: `min(MTU - 3, 512)` байт.
3. **Финальный пакет (маркер окончания передачи):**
   ```text
   END_FILE\n
   ```
*Если файл не найден, возвращается:* `ERROR: File not found: <filename>\nEND_FILE\n`.

##### 3. Ответ на `WIFI`:
```text
WIFI:Trackify:12345678\n
```

## 2. Функционал Мобильного Приложения (Flutter - moto_lap_timer)

### Интерфейс пользователя (UI)
1. **Кнопка BT (Bluetooth):**
   - Находится в нижней навигационной панели (Bottom Navigation Bar) рядом с кнопкой добавления трека (`+`).
   - Иконка — стандартный значок Bluetooth.
2. **Окно поиска и синхронизации:**
   - При нажатии на кнопку BT открывается модальное окно или новый экран.
   - Приложение запрашивает права на использование Bluetooth (и геолокации, если требуется ОС).
   - Выполняется автоматический поиск устройства с именем `Trackify`.
3. **Список файлов:**
   - После успешного подключения приложение отправляет команду `LIST`, считывает список до получения маркера `END_LIST\n` и отображает полученные файлы.
   - Каждый элемент списка содержит:
     - Имя файла (например, `log_001.bin`).
     - Размер файла в мегабайтах (МБ).
     - Кнопку **"Скачать"**.
4. **Процесс загрузки:**
   - При нажатии "Скачать" приложение отправляет команду `GET log_XXX.bin`.
   - Логер сначала отправляет `FILE:<name>:<size>\n`, позволяя приложению инициализировать точный прогресс-бар.
   - По мере прихода пакетов данных приложение обновляет индикатор прогресса.
   - При получении маркера `END_FILE\n` скачивание считается завершённым.
5. **Интеграция с созданием заезда:**
   - Скачанный файл (`.bin`) сохраняется во временное хранилище телефона.
   - Приложение парсит файл с помощью `TrackifyBinParser` (согласно [trackify_bin_format_spec.md](trackify_bin_format_spec.md)) и открывает экран `RaceCreationScreen`.
   - Пользователь видит трек на карте и размечает финишную линию / проводит анализ кругов.

### Ограничения и особенности
- **Бинарный формат `.bin`:** По сравнению с устаревшим NMEA `.txt`, бинарный формат UBX-NAV-PVT компактнее примерно на ~76%, благодаря чему скачивание по BLE происходит значительно быстрее (~285 КБ за 5-минутную сессию на 25 Гц).
- **Удержание экрана:** Во время передачи файла рекомендуется не сворачивать приложение, чтобы операционная система не оборвала BLE соединение.

## 3. Сценарий взаимодействия

1. Мотоциклист завершает заезд.
2. Подходит к трекеру (Trackify) и зажимает кнопку на 4 секунды. Трекер переходит в режим Wireless Sync (мигает бирюзовый светодиод).
3. На телефоне открывает приложение **Moto Lap Timer** и нажимает иконку **Bluetooth** в нижней панели.
4. Приложение находит трекер, подключается, отправляет `LIST` и выводит список заездов.
5. Мотоциклист видит последний файл (например, `log_012.bin`, размер `~285 КБ`) и нажимает "Скачать".
6. Через 5-15 секунд файл скачан, приложение автоматически парсит бинарные данные и открывает экран анализа трека (`RaceCreationScreen`).
7. Пользователь размечает круг и сохраняет заезд. Трекер можно вернуть в обычный режим коротким нажатием на кнопку.
